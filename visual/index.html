One append, one partition

A topic is three logs here. The key picks the log. The offset is just the next slot in that log. Followers and the high watermark sit under the logs: a consumer is only allowed to read a record after every in-sync replica has it.

BatchProducer holds records, then sends a batch.
Partitionmurmur2(key) picks the leader.
AppendLeader writes the next offset.
High watermarkVisible once the ISR has it.

What the cluster adds

This page is one broker's worth of logs. In the Compose cluster each partition has a leader and two followers. acks=all returns only after the in-sync replicas append the same batch. The high watermark is that agreed offset. Consumers do not read past it.

Leave the key blank and the record uses the sticky partitioner: several unkeyed records share one partition, then the producer switches. A key does not stick by accident. It is toPositive(murmur2(key)) % 3, the same function the Java client uses. Try alice twice.
